# Shorts Studio

A rights-first, originality-first production system for YouTube Shorts. It
takes a topic through a pipeline:

```
TREND/IDEA → RESEARCH → SOURCE DISCOVERY → RIGHTS CHECK → SOURCE ANALYSIS → ORIGINAL ANGLE
→ SCRIPT (5 scored hooks) → FACT CHECK → NARRATION → STORYBOARD → RENDER + CAPTIONS + AUDIO MIX
→ QC GATE → HUMAN REVIEW → (optional) OFFICIAL YOUTUBE API UPLOAD → ANALYTICS → EXPERIMENTS
```

What it will not do:

- It is **not** a downloader or re-upload tool.
- Source footage is used only with a verified rights record. Uncertain rights mean rejection.
- Every video needs a person's approval before upload. Public release needs explicit permission.
- `DRY_RUN=true` and `AUTO_PUBLISH=false` are the defaults, and they are enforced in code.

**TikTok Engine:** a TikTok-first application built on this core library lives in
[tiktok-engine/](tiktok-engine/README.md). It adds trends, format templates,
idea batches, original procedural visuals, a natural local voice, TikTok QC,
and a dry-run Content Posting API client.

For the design, see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). For YouTube
Partner Program facts and what they mean for the business, see
[docs/BUSINESS_RESEARCH.md](docs/BUSINESS_RESEARCH.md).

## Quick start

```bash
# system tools
sudo apt-get install ffmpeg espeak-ng        # macOS: brew install ffmpeg espeak-ng

python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                          # optional keys; everything runs offline without them

python main.py init
python main.py make-fixtures                  # self-made CC0 Game of Life footage + example research notes
python main.py pipeline --topic "Conway's Game of Life"
```

The last command writes these outputs:

- the video: `renders/<date>_<slug>_video-001.mp4` (1080x1920, H.264/AAC)
- the review page: `exports/<video>/review.html`
- the QC report: `exports/<video>/qc_report.json`
- captions, audio tracks, storyboard, and thumbnails, each in their own folder

The video then waits in `REVIEW`:

```bash
python main.py review --video <video_id>                    # full summary + interactive decision
python main.py review --video <video_id> --approve          # private/unlisted only
python main.py review --video <video_id> --approve --allow-public
python main.py upload --video <video_id>                    # DRY RUN: writes the exact API request
DRY_RUN=false python main.py upload --video <video_id> --live --privacy unlisted
```

## Making your own videos

1. **Choose a niche from data.** Run `python main.py research --niche-report`. It
   produces a table of measured facts, estimates, and assumptions. It does not
   rank niches; the choice is yours.
2. **Find topics.** Run `python main.py research --trends` (manual ideas,
   Wikipedia pageviews, RSS, and YouTube mostPopular with an API key). Or pass
   `--topic`.
3. **Research.** Write `research/notes/<topic-slug>.yaml`. It holds facts in your
   own words, each citing at least one source, optionally with `tags`,
   `question`, and `requires`. See the example generated by `make-fixtures`. With
   network access, the Wikipedia provider adds cited evidence. Its CC BY-SA
   prose is never narrated verbatim.
4. **Add footage you're allowed to use.** Put it in `sources/library/` with a
   `<file>.rights.yaml` sidecar recording the license, creator, reference, and
   date. Or enable the Commons, NASA, and Internet Archive providers (network).
   Anything without verifiable rights is rejected. Human verification is
   available with `verify-sources --approve ID --reference ... --date ...`.
5. **Write the script.** Set `content.llm_provider: anthropic` and
   `ANTHROPIC_API_KEY` for model-written scripts. The offline writer arranges
   your notes, which only works as well as the notes do.
6. **Choose a voice.** Set `voice.provider: elevenlabs` with `TTS_API_KEY` and
   `ELEVENLABS_VOICE_ID` for a natural voice. espeak-ng is robotic and meant for
   development only.

## Commands

| Command | What it does |
|---|---|
| `research --topic T` / `--trends` / `--niche-report` | Topic research, trend discovery, niche data report |
| `discover-sources --topic T` | Search providers → rights gate → ingest approved → analyse |
| `verify-sources [--approve ID \| --reject ID]` | List rights records; record a human rights decision |
| `generate-script --topic T [--duration 30]` | Blueprint, 5 hooks, script, fact check |
| `generate-video --video ID` | Narration, audio, captions, storyboard, render, thumbnails, QC |
| `qc --video ID` | Re-run the QC gate |
| `review [--video ID] [...]` | APPROVE / REJECT / EDIT (title, description, script) / RENDER_AGAIN / SCHEDULE |
| `upload --video ID [--privacy] [--live]` | Official YouTube Data API upload (dry run by default) |
| `analytics [--collect \| --import-csv F \| --record ID ...]` | Timestamped analytics snapshots |
| `experiments create/assign/analyze/list` | Controlled comparisons with a minimum sample size |
| `dashboard` | `exports/dashboard.html`: KPIs, groupings, descriptive "what is working" |
| `costs` | COST_PER_VIDEO, per 100, and per 1000 (estimates from `config/pricing.yaml`) |
| `finance [--hypothetical-rpm X]` | Actual revenue and costs; labelled hypothetical scenarios |
| `calendar` / `status` | Content queue by state; recent errors and safety switches |
| `pipeline --topic T` / `--auto-research` / `--resume ID` | The full run |

## Configuration

`config/settings.yaml` holds the main settings:

- **Channel:** `NICHE`, `LANGUAGE`.
- **Production:** `TARGET_DURATION`, `VIDEO_RESOLUTION`, `POSTING_FREQUENCY`,
  `MAX_DAILY_VIDEOS`.
- **Voice and presentation:** `VOICE`, `CAPTION_STYLE`, `MUSIC_POLICY`.
- **Sources:** `SOURCE_POLICY`.
- **Publishing:** `AUTO_UPLOAD`, `MANUAL_APPROVAL`, `DRY_RUN`, `AUTO_PUBLISH`.
- **Costs:** `MAX_API_COST`.

Other config files:

| File | Contents |
|---|---|
| `caption_styles.yaml` | Caption styles |
| `style.yaml` | Banned openings and phrases, hype limits |
| `niches.yaml` | Seeds and editable priors for the niche report |
| `pricing.yaml` | Your unit prices |
| `pronunciations.yaml` | Pronunciation lexicon |
| `topic_ideas.yaml` | Manual topic ideas |

Secrets go only in `.env`, which is git-ignored and redacted from logs.

`pytest` to check yours.

## Known limitations

- **espeak-ng voice:** robotic. Publish with a natural TTS provider. QC flags this as a risk.
- **Offline writer:** its narration quality depends on your notes. For
  consistently good storytelling, use the LLM writer and edit its drafts in review.
- **Fact checker:** it proves *traceability* (every sentence matches a cited
  research record; numbers must match exactly). It does not establish truth.
  The reviewer sees every claim with its source.
- **Watermark detection:** heuristic. A positive result blocks QC; an
  inconclusive one is flagged for a person.
- **Legal and policy judgement:** the rights engine is conservative, but it
  is not legal advice. Keep your license evidence; `licenses/` stores a snapshot
  per source.
- **Maps and animated timelines:** not built yet (see the roadmap).
